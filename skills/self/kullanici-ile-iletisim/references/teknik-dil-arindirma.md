# Teknik Dilden Arındırma Kuralı (17.08.2026)

Bilal teknik sistem/proje analizlerinde **günlük dil** ister.

## Kural

"Teknik dilden arındırarak anlat" dediğinde:
- Jargon, kod, terminal çıktısı, teknik terim → **yasak**
- Basit, düz, herkesin anlayacağı dil → **zorunlu**
- Tablo ve madde işe yarıyor ama içi teknik olmamalı

## Dönüşüm Desenleri

| Teknik | Günlük |
|--------|--------|
| Node.js 16 + React 19 + Tailwind v4 | Hızlı ve modern bir site altyapısı |
| drag-drop kanban pipeline | Müşterilerini sürükleyerek bir aşamadan diğerine taşıyorsun |
| Supabase auth | Şifre ile giriş sistemi |
| RAG tabanlı cevaplama | Soru sor, kaynaklı cevap al |
| Bilingual TR/EN toggle | Türkçe/İngilizce değiştirme seçeneği |
| Forecasting | Gelir tahmini |
| KPI kartı | Özet bilgi kutusu |

## Örnek Uygulama (Pipely, 17.08.2026)

"pipely'yi detaylı anlat" isteği geldiğinde teknik değil, sadece "ne işe yaradığını" anlattım — memnun kaldı.

Format:
1. Basit tanım (1 cümle)
2. "Ne yapıyor?" (günlük dilde maddeler)
3. "Her sayfada ne var?" (basit açıklamalar)
4. "Ne zaman işe yarar?" (pratik kullanım)
5. "Ne eksik?" (dürüst özet)

## Kural

Proje/sistem/ürün anlatırken ÖNCE "bu ne işe yarar?" sorusunu cevapla, TEKNİK DETAY'i sadece sorulursa ver.
